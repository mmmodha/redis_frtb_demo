## How to re-run this clause-trace live

The §21.4 live values were captured by smoke-run-15 (Wave 5.15s, 2 000 rows). The §21.5 live values were captured by smoke-run-16 (Wave 5.16e2, 6 000 rows = 2 000 each Delta/Vega/Curvature) on the same standalone Redis Cloud DB. To regenerate either call, the call shape is:

```
curl -sS -X POST -H 'content-type: application/json' \
  -d '{"risk_class":"GIRR","sensitivity_type":"Delta"}' \
  http://localhost:8080/calc/sbm
```

Substitute `"Vega"` or `"Curvature"` for the other §21.4 row or the §21.5 rows; substitute `"EQUITY"` or `"FX"` for the cross-risk-class variants. The response body's `per_bucket[*].{K_b,S_b,count}` array maps 1-to-1 onto §21.4 clauses 3+4 (or §21.5 clauses (2)+(3)) — one row per bucket — and the top-level `charge` field is the §21.4(5) / (5)(b) or §21.5(5) / (5)(b) output. Code paths above stay valid regardless of which DB serves the FCALL — they are sharded by `sens:{risk_class:bucket}:*` hash-tag, so each per-bucket FCALL stays slot-local on whichever Redis topology is in use.

**Curvature bootstrap closure (Wave 5.16f1)**: `services/api/src/bootstrap.ts:buildFrtbSnippets` now registers all 9 snippets at api startup (6 Delta/Vega + 3 `*_curvature`); clean-room `docker compose up` produces the full 9-variant matrix without runtime helpers. Regression-pinned by the "registers all 9 (risk_class × leg) function names" assertion in `services/api/tests/bootstrap.test.ts`.
