## Named hypothesis for Wave 5.15j — `tools-profile-build-bypass`

The Wave 5.15h gate (`docker compose up -d --build --wait`) builds only the
services that the default `up` set actually starts. Because the `generator`
service was moved to the `tools` profile in Wave 5.15d.2 (`profiles: ["tools"]`
in `docker-compose.yml`), Compose does not select it for the default `up`,
and therefore `--build` skips it. The Wave 5.15h runbook change was a
necessary but not sufficient fix: the rebuild flag is honoured, but it does
not reach the one image whose source was actually fixed in Wave 5.15f.

Both `compose run --rm generator …` (step 4 invocation) and `compose build
generator` (the only way to rebuild a tools-profile service ahead of time)
would resolve this. The minimal runbook change for Wave 5.15j is to insert
**`docker compose build generator`** (or use `docker compose --profile tools
build generator`) **before** the step-1 `up`, OR to instruct `compose run`
at step 4 to use `--build` — which Compose v2 supports for `run` and which
forces a per-invocation rebuild of the named service:

    docker compose run --build --rm generator --rows 300000 --classes GIRR,EQUITY,FX

Either approach makes the Wave 5.15f case-mismatch fix actually reach the
image that step 4 runs. No application/schema/Docker code change is
implied — this is a runbook-only fix for Wave 5.15j.
