## Single named hypothesis for Wave 5.15h

**`generator-image-rebuild-required-after-5.15f`** — the Wave 5.15f
source fix to `services/generator/src/row-generator.ts` (line 21,
PascalCase `["Delta", "Vega"]`) is correct in git but did not propagate
to the running container because the runbook step 1
(`docker compose up -d --wait`) does not pass `--build`, and Compose
reused the 2026-05-27 pre-fix image. The on-disk
`"sensitivity_type":"DELTA"` (UPPERCASE) sampled from the live cluster
this run is direct evidence the stale generator binary was active. The
fix family is purely procedural / build-pipeline:

1. Either add `--build` to runbook step 1 (single-line runbook change), or
2. Run `docker compose build generator` as a new mandatory pre-flight
   step **after** any commit that touches `services/generator/src/`, or
3. Lock the workflow with a `--pull --build` policy at the runbook /
   CI layer so any source change to a service that ships in a Docker
   image is forced to rebuild before smoke runs.

No application/schema/Lua code change is required; the Wave 5.15f code
fix is already correct. Once a rebuilt generator image is in place,
`sensitivity_type` will be emitted as `"Delta"` / `"Vega"`, the Lua
PascalCase filter will match every row, and AC1 is expected to pass.

A second, independent issue worth keeping on the backlog (lower
priority; does not break AC1 once 5.15h lands): the generator still
emits 300 k stream entries that collapse to ~124 k unique sens:* hash
keys (smoke-run-9: 126 k; this run: 124 k — same fingerprint). This is
what dropped the density gate from 80 % target to 41 %. Investigate
whether the generator's `sens:{trade_id}:{factor}` key derivation is
intentionally collision-prone or whether it should include a
sequence/timestamp suffix.
