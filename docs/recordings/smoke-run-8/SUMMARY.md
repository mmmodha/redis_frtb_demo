## Single named hypothesis for Wave 5.15d

**`calc-preflight-cluster-routing`** — the precondition probe in
`services/api/src/routes/calc.ts` lines 161–187 issues `FT.SEARCH idx:sens
"@risk_class:{X}" LIMIT 0 0` via the shared ioredis Cluster client. With
the current schema, all sens:* keys collapse to one master (hash-tag),
so the per-shard routing of FT.SEARCH can land on the empty master and
read 0 — triggering `503 no-data-or-index` even though `FT.INFO num_docs`
reports the populated total. Companion concern: cluster OOM cap (~737 M
per shard) is reached when the autostart generator pumps its 2,000,000-row
default into a 2 GB total cap, evicting ~80 % of consumed rows under
`volatile-lru` and capping `idx:sens` growth. Wave 5.15d should scope
one (or split into 5.15d / 5.15e) of:

1. Make calc.ts precondition use `FT.INFO num_docs` (cluster-aggregated)
   or a multi-shard SCAN-fanned FT.SEARCH instead of single-shot
   FT.SEARCH.
2. Tune autostart generator default `--rows` to fit the 2 GB cap, or
   disable autostart in the smoke compose and rely on the explicit
   `compose run --rm generator --rows N` step 4 invocation.
